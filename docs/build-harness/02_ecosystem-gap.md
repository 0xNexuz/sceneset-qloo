# Ecosystem Gap

Status: **VALIDATED FOR BUILD**

Qloo exposes entity resolution, cross-domain affinity, location filters, tags, and explainability, but small event teams still lack a focused workflow that turns those primitives into an auditable market-and-program decision.

The application shell and policy engine are portable, but the cultural decision core is not equivalent without a taste graph. Qloo is load-bearing because it resolves heterogeneous cultural entities and ranks cross-domain candidates using structured affinity and location signals.

| Solution | Missing for this use | SceneSet difference |
|---|---|---|
| Generic concierge | No market decision or audit trail | Typed comparison plus receipt |
| Tour routing tool | Optimizes distance, not cultural fit | Taste is primary; logistics are constraints |
| Audience dashboard | Does not execute a workflow | Agent composes and verifies one plan |
| Qloo API directly | Requires application logic | Reusable decision and evidence layer |

Without SceneSet, developers still must design market normalization, constraint enforcement, bounded retries, evidence capture, and a user-facing receipt. The durable advantage is validated briefs, policy rules, outcome feedback, and receipts—not an LLM prompt.
